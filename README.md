# 과제 15: 퀵 정렬과 AVL 트리 정렬의 성능 비교

## 1. 실험 방법

- 데이터: n = 1,000 ~ 20,000의 난수(중복 허용). 두 방법에 같은 데이터와 같은 삽입·삭제 순서를 사용했고, 마지막에 결과가 같음을 확인했습니다.
- 퀵 정렬: **피벗은 구간의 가운데 원소**입니다. 삽입·삭제는 선형 탐색 후 뒤의 데이터를 한 칸씩 이동합니다.
- AVL 트리: 같은 데이터를 하나씩 삽입하고 회전으로 균형을 맞춥니다. 같은 값은 `count`에 저장합니다.
- 측정: 시간은 정렬 시작부터 마지막 삽입·삭제까지입니다. 비교 횟수는 데이터 값끼리의 비교이고(균형 인수는 제외), 이동 횟수는 값의 복사·대입입니다(포인터 변경과 `count` 증감은 제외). 메모리는 자료구조 크기와 재귀 스택(추정값)의 합입니다.

## 3. 분석

- **시간과 비교 횟수**: AVL의 비교 횟수가 훨씬 적었습니다(n=20,000에서 약 88배). 배열은 삽입·삭제마다 위치를 처음부터 찾아서 연산 한 번에 최대 n번 비교하지만, AVL은 트리 높이만큼만 비교하기 때문입니다. 시간은 n=1,000에서는 배열이 더 빨랐고, n=4,000 이상에서는 AVL이 2~6배 빨랐습니다. n이 작을 때는 AVL의 `malloc`과 포인터 이동 비용이 더 크기 때문으로 추정합니다. n=20,000의 AVL 시간은 측정 오차가 있는 것 같습니다.
- **이동 횟수**: 배열은 삽입·삭제 때 뒤의 데이터를 모두 옮겨야 해서 n=20,000에서 약 2,980만 회였고, AVL은 포인터만 바꿔서 17,210회였습니다(약 1,700배 차이).
- **메모리**: 배열이 더 적게 씁니다. AVL 노드는 값 외에 `count`, `height`, 포인터 2개가 있어서 32바이트이고, 값 하나에 4바이트인 배열보다 약 5배 많이 썼습니다.
- **크기 증가**: n이 20배가 되면 배열의 비교·이동은 300배 이상 늘었고(n²에 가까움), AVL은 20~30배 늘었습니다(n log n에 가까움). 데이터가 클수록 차이가 커집니다.
- **유리한 자료구조**: 삽입·삭제가 반복되고 데이터가 크면 **AVL 트리**가 유리합니다. 탐색과 이동이 O(n)인 배열과 달리 AVL은 O(log n)이기 때문입니다. 다만 메모리를 더 쓰고, n이 작거나 삽입·삭제가 거의 없다면 배열과 퀵 정렬로 충분합니다.

※ 시간은 한 번만 측정한 값이라 실행마다, 컴퓨터마다 달라질 수 있습니다.
